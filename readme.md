# Telegram Bot — README

## 📌 Описание проекта
Этот проект представляет собой Telegram‑бота, который обрабатывает текстовые запросы, изображения, вложения, формирует 
документы и работает с базой данных. Логика бота разделена на модули: обработчики, сервисы для текстов и изображений, 
взаимодействие с ИИ, а также функции для работы с файлами.

Бот запускается локально через Python и использует конфигурацию из файла `.env`.
Обращение к боту происходит в Telegram по имени: @nco_postgenerator_bot

## 🚀 Запуск проекта
### 1. Установить зависимости
```bash
pip install -r requirements.txt
```

### 2. Создать файл `.env`
Пример:
```
TELEGRAM_BOT_TOKEN= тут_токен_бота
YANDEX_FOLDER_ID= ID_папки_с_console.yandex.cloud
YANDEX_OAUTH_TOKEN=токен_полученый_https://oauth.yandex.ru/verification_code
YANDEX_IAM_TOKEN=API_полученый_на_console.yandex.cloud
```

### 3. Запустить бота
```bash
python run.py
```
Бот автоматически подключится к Telegram и начнёт обрабатывать сообщения.

## 🧩 Краткое описание решения
Бот построен на модульной архитектуре:
- **Handlers** — обрабатывают команды и сообщения пользователей.
- **Services** — изолируют бизнес‑логику: создание текстов, взаимодействие с AI, 
    обработка изображений, работа с вложениями.
- **DB и конфиг** — обеспечивают хранение данных и управление настройками.
- **run.py** служит точкой входа, инициализирует бота и запускает обработчики.

Такое разделение делает проект легко расширяемым, удобным для сопровождения и добавления функционала.

## 🔧 Технические детали реализации
Ниже приведено подробное описание того, как устроены ключевые части бота, включая особенности архитектуры, 
обработку данных, принципы разработки и расширяемость.

### ⚙️ Архитектура
Проект построен по принципам модульности и разделения ответственности. Это позволяет:
- легко добавлять новые функции, не изменяя имеющийся код;
- тестировать отдельные компоненты независимо;
- избегать дублирования логики;
- упрощать отладку.

Основные слои архитектуры:
1. **Уровень взаимодействия с Telegram API** — библиотека aiogram, которая отвечает за обработку апдейтов, 
    роутинг сообщений, регистрацию команд.
2. **Уровень обработчиков (handlers)** — принимает входящие данные от Telegram и вызывает соответствующие сервисы.
3. **Сервисный уровень** — вся бизнес‑логика: генерация текстов, работа с ИИ, 
    обработка изображений, взаимодействие с файлами.
4. **Уровень данных** — SQLite‑база данных, используемая для сохранения информации.
5. **Инфраструктурный уровень** — конфигурации, .env, стартовые скрипты.

### 🧠 Работа с AI
Файл `ai_service.py` отвечает за взаимодействие с AI‑моделями. В зависимости от задачи бот может:
- генерировать текстовые ответы;
- редактировать текст по заданию пользователя;
- формировать структурированные документы (отчёты, планы, списки);
- выполнять анализ вложений.

Обработка запроса происходит так:
1. Обработчик принимает сообщение.
2. Передаёт текст или файл в соответствующий сервис.
3. Сервис формирует запрос к ИИ.
4. Ответ ИИ преобразуется в итоговый формат.
5. Обработчик возвращает результат пользователю.

### 🖼️ Работа с изображениями
`image_service.py` позволяет:
- анализировать изображения;
- генерировать новые изображения (если настроено);
- получать текстовое описание изображения;
- использовать изображения как часть более сложных сценариев.

### 📎 Работа с файлами
`attachment_service.py` выполняет операции:
- сохранение файлов на диск;
- анализ типа файла;
- конвертация в нужный формат;
- передача данных в другие сервисы.

Это особенно важно для функций генерации документов.

## 🧱 Структура handlers
Для удобства поддержания проекта обработчики разделены по функциональным модулям:

- **handlers_nco.py** — работа с НСО‑данными, формирование документов.
- **handlers_text_create.py** — генерация текстов.
- **handlers_text_edit.py** — редактирование текстов.
- **handlers_plan.py** — создание планов, структур, дорожных карт.

Каждый файл содержит:
- роутеры;
- функции‑обработчики;
- вспомогательную логику.

## 📚 Примеры сценариев работы бота
### 1. Пользователь отправляет текст → бот создаёт структурированный документ
1. Пользователь пишет: «Создай план проекта по теме X».
2. Handler вызывает text_service.
3. text_service формирует запрос к ИИ.
4. Полученный план форматируется и отправляется пользователю.

### 2. Пользователь отправляет фото → бот анализирует изображение
1. Фото отправляется в image_service.
2. Выполняется анализ содержимого.
3. Бот выдаёт описание или использует изображение в документе.

### 3. Пользователь загружает файл → бот обрабатывает вложение
1. attachment_service определяет тип.
2. Выполняется преобразование или анализ.
3. Результат отправляется пользователю.

## 🧪 Тестирование и отладка
Проект позволяет удобно отлаживать функционал благодаря модульности.

- запускать бота в режиме polling для локальной отладки;
- закрывать токены и ключи ИИ только через `.env`.
